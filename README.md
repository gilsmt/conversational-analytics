# Conversational Analytics

Conversational Analytics imports AI conversation transcripts, extracts structured
insights with Gemini, and lets you explore those insights through a scoped chat
interface.

- **Import** transcripts from a `.zip` or a folder of CSV files.
- **Define** insights to extract and qualifying questions to answer.
- **Analyse** every conversation against those definitions, with progress
  tracking and cancellation.
- **Chat** with an agent over either the whole dataset or a single transcript,
  with persistent threads per scope.

## Stack

| Layer | Technology |
| --- | --- |
| Frontend | Next.js 16, React 19, TypeScript, Tailwind CSS 4, Biome, shadcn/Base UI |
| Backend | FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic Settings |
| AI | Gemini via `google-genai` |
| Database | PostgreSQL (asyncpg) |

## Prerequisites

- Node 24+ with Corepack (pnpm 11)
- [uv](https://docs.astral.sh/uv/) with Python 3.14
- A running PostgreSQL instance
- A Gemini API key

## Setup

### 1. Frontend dependencies

From the repo root:

```bash
pnpm install
```

### 2. Backend configuration

Create `packages/server/.env` from the template:

```bash
cp packages/server/.env.template packages/server/.env
```

```env
DATABASE_URL=postgresql+asyncpg://postgres:postgres@127.0.0.1:5432/conversational_analytics
GEMINI_API_KEY=your-key
GEMINI_MODEL=gemini-2.5-flash
```

`GEMINI_MODEL` defaults to `gemini-2.5-flash` if you leave it out. If your
Postgres requires TLS or uses a provider-specific driver, the `DATABASE_URL` is
normalised at startup (`postgresql://` → `postgresql+asyncpg://`).

The frontend reads `packages/client/.env.local` if the API is not on the default
address:

```env
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000
```

### 3. Database and seed data

From `packages/server`:

```bash
uv sync
uv run task db_migrate
uv run task seed
```

`seed` imports the `Conversations/` folder at the repo root, skips any
`session_id` that already exists, and creates three default insights and three
default qualifying questions.

### 4. Run

Backend, from `packages/server`:

```bash
uv run task api
```

Frontend, from the repo root:

```bash
pnpm dev:client
```

Open <http://localhost:3000>.

## Importing your own conversations

The bundled transcripts under `Conversations/` are **synthetic sample data** used
to exercise the UI out of the box. To use your own data, either drop CSVs into
`Conversations/` before seeding, or import them from the UI at runtime.

```bash
cd packages/server
uv run task seed -- --source ../../path/to/your.zip
```

The UI accepts a single `.zip` or a folder selection. Zip extraction and CSV
validation both happen in the backend.

### Transcript format

Each CSV must have a single `session_id` for the whole file, and requires these
columns:

| Column | Notes |
| --- | --- |
| `session_id` | One UUID per file |
| `speaker` | `user` or `assistant` |
| `message_type` | e.g. `text` |
| `content` | JSON object; `content.text` must be non-empty |
| `confidence` | Optional number |
| `created_at` | ISO 8601, must include a timezone |

Source message IDs are discarded; IDs are generated by the database. A
malformed file fails on its own without blocking the rest of the batch.

## Architecture

```
packages/
  client/          Next.js app (app router)
  server/          FastAPI app
    app/
      analysis/    Insight + question analysis runs and progress
      chat/        Thread persistence and the streaming agent
      conversations/ Import, parsing, and conversation CRUD
      insights/    Insight definition CRUD
      qualifying_questions/ Question definition CRUD
      ai/          Shared Gemini helpers
      core/        Settings and error types
      db/          Session and repository base
    models/        SQLAlchemy models
    migrations/    Alembic migrations
  shared/          TypeScript types shared with the client
```

Repositories encapsulate queries and return updated domain objects; the API layer
owns the transaction boundary and commits at the end of each request. Background
analysis workers commit at the end of each task.

Chat streams over SSE with `token`, `status`, `error`, and `done` events.
Aborting the request stops generation and persists only the user message. The
Gemini tools available to the agent are read-only and never exposed to the client.

## Development

There is no automated test suite. Before considering a change done:

```bash
cd packages/server
uv run ruff check .
uv run ruff format --check .

cd ../../
pnpm lint:client
pnpm type-check:client
pnpm --filter client build
```

Then exercise the affected flow manually: import, insight and question CRUD, an
analysis run and cancel, the dashboard, both chat scopes, stop behaviour, and
conversation cascade delete.

CI runs the commands above on every push and pull request.

## Notes

This app has no authentication and allows CORS from any origin. It is intended to
run locally against your own database. See [SECURITY.md](SECURITY.md) before
exposing it to a network.
